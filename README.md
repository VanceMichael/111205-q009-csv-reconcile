# 无稳定行号的供应商快照变更采集

## 能力概览

在 `service.py` 的 CSV 解码与内容摘要入口之上，`collector/` 实现快照到变更流的完整采集：

- **供应商化配置**（`collector/config.py`）：候选键、业务对比列、忽略列、十进制列按供应商声明；数量与金额用 `Decimal` 比较（`1.50` 与 `1.5` 等价），忽略列（如备注）不进入行指纹。
- **多重集合快照**（`collector/models.py`）：同键行按业务列指纹计数，重复行保留出现次数；不使用文件行号或 set 去重，行重排与备注改动不产生事件。
- **差分与歧义**（`collector/diff.py`）：等价行先按次数抵消；剩余出现枚举全部互异配对方案。方案唯一时产出新增、移除与可解释的逐列数量/金额变更（带行证据）；同一候选键存在多个不等价方案时挂起为歧义，交人工确认，不做排序配对猜测。
- **完整性门禁**（`collector/ingestion.py`）：只有编码/结构合法、业务列可规范化、实际行数与来源声明一致且声明完整的文件才能成为基线；截断、坏行、声明行数不符与半份投递一律拒绝，不贡献删除事件。
- **编排与幂等发布**（`collector/engine.py`、`collector/sink.py`、`collector/store.py`）：状态全量落盘、原子写入、重启可恢复；事件与歧义按内容寻址 ID 去重，重复观察同一文件或重启不会重复发布；人工确认绑定前后输入文件摘要，旧判断不能解释新文件；较老快照晚到只可查阅、不能回退基线；下游 ack 前生成变更所需的基线受保护、不会被清理。

`service.py` 保持已有规范化接口。根目录 `test_service.py` 为原有回归测试，`tests/test_baseline.py` 会同时加载原测试和离线演示验证。

## 环境和运行

使用 Python 3.11.10，仅依赖标准库，无需登录账号、安装第三方包或下载数据。`.python-version` 固定解释器版本；`pyproject.toml` 仅登记 unittest 入口，项目不需要打包安装。

在仓库根目录执行：

```sh
python3 -m unittest discover -s tests -v
python3 demo.py
```

处理不可信输入时可加隔离模式（`-I` 不加载当前目录与环境变量，测试通过 `tests/context.py` 按文件位置注入仓库根，`demo.py` 内部也做了同样的路径引导）：

```sh
python3 -I -m unittest discover -s tests -v
python3 -I demo.py
```

完整演示命令：

```sh
python3 -m unittest discover -s tests -v && python3 demo.py
```

演示实时读取合成输入并运行采集引擎，通常在 90 秒以内结束，不回放历史日志。状态写入临时目录，重复执行结果完全一致且不污染仓库；没有任何网络访问。

## 演示覆盖的场景

`demo.py` 按顺序展示：行重排不产生事件、数量更正为可解释变更、半份同名文件被拒后由完整文件覆盖、同键多方案歧义的人工确认（确认绑定文件摘要、重复提交幂等）、同指纹重复次数变化（多重集合计数）、较老快照晚到不回退、重跑同一文件不重复发布、重启后状态与投递箱一致、坏行与截断拒绝、以及下游 ack 前后的基线保留与回收。

## 合成来源

`fixtures/snapshots.json` 声明对比列、忽略列、十进制列和完整性，`fixtures/snapshots` 保存前后 CSV，保留重复行、行重排、截断、更正与歧义样本（`day3.csv` 展示纯重复次数变化）。`fixtures/inbox` 为早期投递样例，内容校验和可独立验证。全部本地合成，无外部附件。
